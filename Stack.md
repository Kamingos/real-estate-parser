# Стек

- frontend — React;
- api — ASP.NET Core;
- parser-1, parser-2, parser-3 — парсеры на Python;
- data-processor — обработка, нормализация и дедупликация;
- postgres — основная база данных;
- kafka — очередь сообщений;
- nginx — маршрутизация запросов.
- docker — для контейнеризации

# План

## Этап 1. Выбрать предметную область и источники
Результат: утверждённый план сбора данных
- Выбрать книги или электронику.
- Найти три сайта с каталогами одной категории.
- Проверить, что данные доступны без авторизации и их разрешено собирать.
- Определить ключ дедупликации для выбранной области.
- Проверить, реально ли получить минимум 1000 уникальных позиций с каждого сайта.
  Важно: этот этап нельзя пропускать. Если источники неудобны для парсинга или не содержат необходимых полей, весь проект будет сложнее.

## Этап 2. Спроектировать PostgreSQL
Результат: ER-диаграмма и SQL-миграции
- Спроектировать products, offers, sources, attributes и при необходимости raw_products.
- Определить первичные и внешние ключи, ограничения и типы данных.
- Продумать хранение истории цен и времени парсинга.
- Добавить индексы для поиска, фильтрации и связей.
- Создать SQL-файл для создания схемы.
  На этом этапе можно наполнить БД тестовыми данными, не дожидаясь готовности парсеров.

## Этап 3. Написать парсеры на Python
Результат: три набора сырых данных
- Создать общий формат данных для всех источников.
- Написать по одному парсеру для каждого сайта.
- Обрабатывать ошибки сети, ограничения частоты запросов и отсутствующие поля.
- Сохранять результат в JSON или CSV.
- Проверить количество и уникальность записей.
  Сначала добейся стабильной работы на 20–50 позициях, затем запускай полный сбор. Не нужно сразу подключать Kafka.

## Этап 4. Очистка и дедупликация
Результат: единый каталог товаров
- Нормализовать пробелы, регистр, бренды, модели и идентификаторы.
- Удалить повторные записи одного и того же предложения.
- Сопоставить товары из разных источников.
- Сохранять все исходные предложения у одного итогового товара.
- Проверить ложные объединения и пропущенные совпадения.
  Подготовь отдельный набор контрольных примеров, где заранее известно, какие товары одинаковы, а какие различаются.

## Э. тап 5. Подключить Kafka
Результат: асинхронный конвейер данных
- Создать топик, например raw-products.
- Настроить парсеры на отправку сообщений.
- Реализовать обработчик, читающий сообщения из Kafka.
- Добавить валидацию и нормализацию данных.
- Настроить повторную обработку ошибок и защиту от повторной записи.
  Сообщение должно содержать источник, URL, исходные поля и время сбора. Обработчик должен быть идемпотентным: повторное получение сообщения не должно создавать дубликаты.

## Этап 6. Создать API на C#
Результат: работающий backend
- Создать ASP.NET Core Web API.
- Подключить PostgreSQL через EF Core и Npgsql.
- Реализовать миграции и доступ к данным.
- Добавить Swagger/OpenAPI.
- Написать тесты для запросов и бизнес-логики.
  Минимальный набор маршрутов:
  Метод и маршрут	Назначение
  GET /api/products?q=...	Поиск товаров
  GET /api/products/{id}	Карточка товара
  GET /api/products/{id}/offers	Предложения всех сайтов
  GET /api/sources	Список источников

Это соответствует требованию задания о поиске и просмотре товара с предложениями из разных источников. Задание по БД 1.docx

## Этап 7. Разработать React-интерфейс
Результат: готовое пользовательское приложение
- Страница каталога с поисковой строкой.
- Список результатов с названием, изображением и минимальной ценой.
- Фильтрация и сортировка.
- Отдельная страница товара.
- Таблица предложений с ценами и ссылками на сайты.
  Это минимальный обязательный интерфейс по заданию. Задание по БД 1.docx

## Этап 8. Docker Compose и Nginx
Результат: единый запуск проекта
- Создать Dockerfile для API, фронтенда и Python-сервисов.
- Описать контейнеры PostgreSQL, Kafka и приложения в compose.yaml.
- Добавить постоянный том для данных PostgreSQL.
- Настроить Nginx для раздачи React и проксирования /api.
- Проверить запуск с чистого окружения одной командой.
  Docker Compose как раз предназначен для описания и запуска многоконтейнерного приложения.

## Этап 9. Тестирование и сдача
Результат: воспроизводимый и документированный проект
- Проверить сбор данных: не менее 1000 уникальных позиций с каждого сайта.
- Измерить качество дедупликации.
- Проверить SQL-запросы и планы выполнения.
- Сделать скриншоты интерфейса и ER-диаграммы.
- Подготовить README с архитектурой, запуском и описанием алгоритма объединения.
- Проверить, что весь проект запускается через Docker Compose.
